## Anti-Patterns Verdict

**Does this look AI-generated? No.** This is a designed site with a point of view, not a template fill.

**LLM assessment:** Strong, committed POV ("The Calibrated Signal"). The pure near-black surface with zero chroma + one campari-crimson is a deliberate Linear-register choice, not the default SaaS-cream or navy-violet. The bespoke `SignalMotif` hero SVG (a crimson trace that oscillates, decays, and locks flat on a grid) is a signature no template ships. It avoids every absolute ban: no side-stripes, no gradient text, no glassmorphism, no hero-metric template, no identical card grid, no tracked all-caps eyebrows (the credential `.pill` is sentence-case with a crimson dot — the deliberate No-Eyebrow replacement), no numbered-section scaffolding (the install 1/2/3 is a genuine ordered flow, not decoration), no resting shadows. The product's voice ("Ship current Luau with confidence", warm-not-shaming) lands.

**Deterministic scan** (CLI detector over built `dist/*.html`, exit 2 — the `.astro` source scan returned a false-clean `[]` because the detector doesn't parse `.astro`; building first was necessary):
- `flat-type-hierarchy` (warning) — `dist/index.html`, `dist/skills/index.html`. Seven small-text sizes (12, 13, 14, 15, 16, 17, 17.6px) crowded in a 1.5:1 band. The heading scale (h1→h2→h3) carries real hierarchy, but the small-text tier is over-graduated.
- `em-dash-overuse` (warning) — home (13) + all 15 skill detail pages (6–8 each). **Partial false positive:** skill-page counts are inflated by the decorative `aria-hidden="—"` bullet markers in the "What it covers" lists. The real body-copy em-dashes (home ~9–10) are editorially intentional and specific (e.g. *"Deprecated since the Animator refactor — still the top result…"*) — not the generic AI-connective cadence. Flagged anyway, see P2.
- **Banned-pattern list: clean.** Neither detector flagged side-stripes, gradient text, glassmorphism, hero-metric, identical card grids, eyebrows, numbered scaffolding, or text overflow. Corroborates the LLM assessment.

**Browser overlay** (in-page `/detect.js` injected on 3 representative pages — home, `/skills`, `/skills/roblox-gamepasses`; preflight mutation succeeded, script loaded and ran):
- `line-length ~92 chars/line (aim <80)` — flagged consistently (home 1×, `/skills` 2×, `roblox-gamepasses` 3×). This is a rendered-text metric the CLI source scan cannot see. Verified culprits: `.site-footer__fine` (footer disclaimer, fixed `599px` max-width, no `ch` cap → ~87 chars/line, the widest) and `.install__step` descriptions (~79 chars/line, constrained only by the grid column). Main body prose (hero lede 46ch, `.lede` 58ch, trust lede 52ch) is within range.

## Overall Impression

A precise, committed, trustworthy marketing site that earns its "current, sourced source of truth for Roblox Luau" positioning through *structure* (evidenced trust architecture, not adjectives) — exactly what PRODUCT.md asks for. The single biggest opportunity: the mobile experience silently breaks. At 390px there is 293px of horizontal overflow that `body { overflow-x: hidden }` clips without scrolling, so the install Copy buttons and the hero signal cursor are rendered off-screen and unreachable. The craft is exceptional everywhere except on the one surface most visitors actually use.

---

## What's Working

1. **Evidenced trust architecture.** "Why trust it" backs every claim with structure — 48 reference files re-verified, a CI workflow link, the three official sources with real `create.roblox.com` URLs — never adjectives. This is PRODUCT.md's "show trust, don't assert" principle made literal, and it's the thing that converts a skeptical, burned visitor.
2. **Bespoke `SignalMotif`.** A custom hero SVG (crimson trace oscillating → decaying → locking flat, with a dashed reference line and a cursor at the locked steady state) instead of a stock illustration or gradient blob. It gives the page a visual signature no template has, and it embodies the product metaphor ("every claim traces back to the Engine API Reference").
3. **Committed restraint.** Pure near-black + one crimson, no resting shadows, no eyebrows, sentence-case credential pills. The design system is faithful to DESIGN.md and sidesteps every saturated AI lane. Restraint this disciplined is rare and is the core of the "not AI slop" read.

## Priority Issues

### [P1] Mobile horizontal overflow is silently clipped
At a 390px viewport, `document.scrollWidth` is **668px vs 375px clientWidth — 293px of overflow**, and `body { overflow-x: hidden }` clips it with no horizontal scroll, so content past 375px is invisible *and unreachable*. Verified offenders:
- `.install__body` renders **668px wide** — the single-skill command `npx skills add nonlooped/roblox --skill roblox-datastores` is `nowrap` and propagates as min-content through the install grid's `1fr` (= `minmax(auto, 1fr)`).
- `.hero__copy` renders **414px wide** — the `npx skills add nonlooped/roblox` command does the same in the hero grid.
- `.codechip` has `min-width: auto` (not `0`), so the flex chip can't shrink below the nowrap command.
- Separately, `SkillsIndex` uses `repeat(auto-fit, minmax(22rem, 1fr))` — `22rem` = 352px, which overflows any phone with <352px content width.

**Why it matters:** On the surface most visitors use, the install Copy buttons (the primary conversion action) and the hero signal motif (the brand signature) are clipped off-screen. A user who can't tap "Copy" on the install command can't install. `overflow-x: hidden` makes this a silent failure — nothing looks broken, it just doesn't fit. Affects home + all 15 skill detail pages.
**Fix:** On every collapsing grid use `minmax(0, 1fr)` instead of `1fr` (Hero, Problem, Trust, Install, `[slug]` mobile breakpoints), add `min-width: 0` to `.codechip` and to the `.hero__copy` / `.install__body` grid items, and lower SkillsIndex to `minmax(18rem, 1fr)`. Then remove the `overflow-x: hidden` band-aid and verify no overflow remains (it's currently masking the bug).
**Suggested command:** `/impeccable adapt site`

### [P1] "current" / "hub" badge text fails WCAG contrast (2.54:1)
The credential badges — `.skill__current` and `.skill__hubtag` on skill pages, and the "current" badge in `OldVsNew` — render crimson text (`oklch(0.53 0.19 22)`) on a 14%-crimson tint over near-black. Computed contrast is **2.54:1**, failing both 4.5:1 (normal text) and 3:1 (large/graphical). Affects home (1 "current" badge in the comparison table), `/skills/roblox-gamepasses` (2 "current"), and `/skills/roblox` (the "hub · entry point" tag).
**Why it matters:** These badges are *trust signals* — "current" is the product's whole credential. A low-vision or color-vision-deficient visitor (and PRODUCT.md names color-vision-safety as non-negotiable) can't read the one word that matters most.
**Fix:** Reuse the `.pill` pattern that already works at 10.55:1 — `ink-soft` text + a crimson dot on `surface`. Or, if the filled look is wanted, solid `crimson` background + `on-crimson` text (5.35:1). Either passes AA.
**Suggested command:** `/impeccable audit site`

### [P2] Footer column labels pollute the document outline
The three footer navigation column labels ("Explore", "Sources", "Project") are marked up as `<h2 class="site-footer__label">`. Because they're top-level `h2`s, a screen-reader heading scan lists them alongside the page's real headings — "Explore / Sources / Project" appear as document sections at the same level as "Why trust it" and "Install."
**Why it matters:** Heading navigation is the primary screen-reader wayfinding method; footer labels injected as `h2` break the mental model of the page structure and send SR users on dead-end detours. This is a semantic/structural a11y defect, not a visual one.
**Fix:** Drop the footer labels to `<h3>` (or make them non-heading `<p>`/`<span>` with a styled class — they're labels, not document sections). Keep the visual treatment identical.
**Suggested command:** `/impeccable audit site`

### [P2] Em-dash density is a brand-coherence risk
The detector flagged 13 em-dashes on the home page and 6–8 on each skill page. The skill-page counts are partly a false positive (decorative `aria-hidden="—"` bullets inflate them), but the home page has ~9–10 real body-copy em-dashes. On inspection they're editorially intentional and specific — *not* the generic AI-connective cadence. **But** this product's entire value proposition is "not confidently-wrong LLM output," and em-dash density is the single most-cited LLM-prose tell. A visitor primed to spot AI prose may read the density as a tell regardless of intent — undercutting the "we're the sourced alternative" message.
**Why it matters:** For most sites this is a non-issue. For a site selling credibility-by-contrast-with-LLM-slop, pattern-matching to LLM prose in your own marketing copy is a brand risk.
**Fix:** A `clarify` pass converting roughly half the em-dashes to colons, periods, or parentheses — enough to drop below the tell-density while keeping the editorial voice. Keep the best ones (the contrastive asides in `Problem.astro` earn their dashes).
**Suggested command:** `/impeccable clarify site`

### [P3] Type polish: over-long footer lines + over-graduated small-text scale
Two detector-confirmed typography issues:
- **Line length:** `.site-footer__fine` renders ~87 chars/line (fixed `599px`, no `ch` cap); install step descriptions ~79 chars/line (column-bound). Both exceed the 65–75ch readability target.
- **Flat type hierarchy:** home and `/skills` use seven small-text sizes (12, 13, 14, 15, 16, 17, 17.6px) in a 1.5:1 band — e.g. `12px` and `13px`, `17px` and `17.6px` are nearly indistinguishable. Too many sizes with too little contrast between steps.
**Why it matters:** Marginal readability and a "too many type sizes" smell. Low severity — the heading scale still carries real hierarchy and main prose is within range.
**Fix:** Cap the footer fine-print with a `ch`-based `max-width` (~60ch); consolidate the small-text ramp to ~3 sizes (e.g. 12px / 14px / 16px) instead of seven.
**Suggested command:** `/impeccable typeset site`

## Persona Red Flags

**Jordan — first-timer, burned skeptic (project-specific):** Arrives expecting AI slop, scans for signals of realness. The skills index reduces each skill to a terse technical one-liner ("current, sourced DataStores patterns") that assumes domain fluency — a first-timer may not orient. Combined with the em-dash density (P2), these are the two elements most likely to read as "AI-generated" to exactly the visitor the product is trying to convince otherwise.

**Riley — mobile practical user:** Hits the 293px silent overflow (P1): the install Copy buttons and hero signal cursor are off-screen and unreachable, so the primary conversion action is effectively unavailable on phone. External links (GitHub, `create.roblox.com` sources) open same-tab, so tapping one to verify a claim loses her place on the site with no easy way back.

**Casey — keyboard/screen-reader user:** The "current"/"hub" badges at 2.54:1 (P1) are unreadable for low-vision/color-vision-deficient users — and "current" is the credential. Footer `h2` labels (P2) pollute the heading outline, sending her on dead-end detours. Off-screen-but-rendered content (the clipped install buttons / hero cursor) exists in the a11y tree with no way to scroll to it.

## Minor Observations

- **Install step numbers `.install__n`** (crimson on the near-black install bg) compute ~3.38:1 — passes 3:1 for large bold text but borderline; worth bumping slightly. (`/impeccable audit`)
- **`SignalMotif` is static.** The "trace oscillating/decaying/locking" metaphor is inherently motion; a subtle one-shot draw-in + lock animation (with a `prefers-reduced-motion` crossfade fallback) would reinforce "calibrated signal" without violating DESIGN.md's "responsive motion only." (`/impeccable animate`)
- **External links open same-tab.** GitHub and `create.roblox.com` source links have no `target="_blank"` + `rel="noopener"`; users lose their place. (`/impeccable polish`)
- **Footer nav tap targets** — `.site-footer .link` at 13px may fall under the 44px mobile tap minimum depending on line-height. (`/impeccable audit`)
- **`--faint` token (2.77:1) is defined but never applied** — dead token, remove during distill. (`/impeccable distill`)
- **`/skills` index has no search/filter** — a returning user hunting one of 15 skills scrolls all 6 groups. Low priority for a 15-item list, but the one H7 gap.
- **404 page is excellent** — on-brand ("This page isn't in the suite… a little like a deprecated API") with two clear exits. Keep as-is.

## Questions to Consider

- The whole product hinges on "current." What if *every* skill row and badge carried a machine-verified "last reviewed" date, not just the one hero pill — making currency a visible, per-item credential instead of a single site-level assertion?
- The `SignalMotif` is the brand signature and it's static. What would a *moving* calibrated signal — one that visibly locks — do for the "every claim traces back" metaphor on first scroll?
- Mobile is where this silently breaks. What would a phone-first re-pass of the grids + CodeChip look like — and is `overflow-x: hidden` currently masking bugs you'd rather see and fix?
- The visitor most likely to convert is the one most likely to spot LLM prose tells. Is the em-dash density worth a copy pass to stay unambiguously below the tell threshold?
